# 主动通知

## 可用渠道

| 渠道 | 工具 | 说明 |
|---|---|---|
| 米家 App 推送 | `miloco_notify_push(notify)` | 文本通知，最通用 |
| 音箱 TTS / 设备播报 | `miloco_device_control` | 先用 `miloco_device_spec` 找到该设备的播报动作，再 `call_action` |
| DSH 对话投递 | `dsh_deliver_message(text, sessionId?, …)` | 把消息送进某个 DSH 会话 |

通知渠道的绑定/解绑由 Miloco 面板管理；本插件没有单独的绑定工具。

## 决策顺序

1. **给谁**：从用户的描述确定对象；涉及具体家人时用 `miloco_person_list` 拿 id，不用名字猜。
2. **走哪**：默认米家 App 推送；家里有音箱且用户要求播报时才用 TTS。
3. **说什么**：一句话说清“发生了什么 + 需要做什么 + 什么时候”，避免监控式措辞。
4. **执行**：调用工具；失败时告诉用户失败原因，不重复轰炸。
5. **降噪**：同一事件短时间内只通知一次；用户表达“别提醒”时记录下来并停止同类通知。

## 文案

- 危险告警：先结论，再地点/时间，最后建议动作。例：“厨房可能燃气未关，22:10 检测到异常，请尽快查看。”
- 日常提醒：短、具体、可执行。例：“21:30 了，该提醒奶奶吃药。”
- 不要编造未确认的人物、地点或严重程度。
- 不要附带设备凭据、内网地址或 token。

## 安全

- 只读模式没有 `miloco_notify_push`，应说明无法主动通知。
- 播报内容会外放，涉及隐私时先确认场景。
- 高风险告警（燃气、跌倒、陌生人闯入）优先推送，不要等用户回复。
