# 候选提升

## 流程

1. `miloco_home_profile(target="both")` 读取正式区与候选区。
2. 逐条判断：
   - 已被正式区覆盖 → 不重复提升，可删除候选。
   - 与正式区冲突 → 用 `update` 修正，说明冲突点。
   - 证据足够且是新的 → 用 `add` 或 `from=<candidate_id>` 提升。
3. 调用 `miloco_home_profile_write(ops)`：
   - `from` 带上候选 id，后端会消费该候选。
   - `entry` 里保留主体、置信度、来源与证据。
4. `miloco_home_profile_commit()` 提交。
5. 复查正式区，确认没有重复条目。

## 判断标准

- 用户明确说过 → 可以提升。
- 多次观察一致 → 可以提升，置信度写实。
- 只出现一次且是推测 → 留在候选区。
- 健康/安全相关但证据弱 → 先问用户。

## 边界

- 不修改与本次提升无关的条目。
- 不把候选区的原始日志整段塞进正式区，只保留结论与证据摘要。
- 只读模式没有写入工具；此时只输出“建议提升清单”。
